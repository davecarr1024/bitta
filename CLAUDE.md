# Bitta

Event-driven digital circuit simulator. Logic emerges from primitive interactions — no special-casing for gates, latches, or any higher construct.

**MVP:** a working D flip-flop built from NAND gates built from switches.

## Language and Tooling

C++20. Use `enum class`, `struct` with explicit constructors, `std::optional`, `std::variant`, `std::unordered_map`, and `std::function` throughout. No third-party simulation libraries — everything is from scratch by design.

```
cmake >= 3.21   # build system
gtest           # tests (fetched automatically via FetchContent)
g++/clang++     # C++20
```

Build and test:

```bash
make            # configure + build + test (alias for `make check`)
make configure  # cmake -S . -B build -DCMAKE_BUILD_TYPE=Debug
make build      # cmake --build build -j
make test       # ctest --test-dir build --output-on-failure -j
make clean      # rm -rf build
```

All targets compile with `-Wall -Wextra -Wpedantic -Wshadow -Wconversion -Werror`.

### Adding a new source file

For INTERFACE (header-only) targets, just add the header under `include/bitta/<module>/`.

When adding the first `.cpp` to a module, switch the target from `INTERFACE` to `STATIC` in its `CMakeLists.txt`:

```cmake
file(GLOB_RECURSE SOURCES "src/*.cpp")
add_library(bitta_core STATIC ${SOURCES})
# (rest stays the same)
```

### Adding a new test

```cmake
# tests/CMakeLists.txt
bitta_test(test_signal test_signal.cpp)
```

## Key Invariants (never violate these)

1. Only nodes hold state — no other object has memory of signal values
2. All influence on nodes is via `set_driver` / `remove_driver` — never mutate `node.current_state` directly
3. Events may only schedule new events at `time >= now` — no past-affecting events
4. Contracts read traces only — they never call anything on `Circuit` or `Node`
5. All circuit construction happens before `Simulator::run()` — no structural changes during simulation

## Code Conventions

- No comments unless the WHY is non-obvious
- No docstrings on functions whose name and types are self-explanatory
- `source_id` strings on `DriveIntent` should be stable and human-readable (e.g. `"vcc:42"`, `"sw_7"`, `"conn_3"`)
- IDs are `std::string`; generated by a global counter or UUID utility
- Default `inertia_delay = 1` for all nodes
- Default `propagation_delay = 1` for all connections

## Testing Conventions

Every component definition has a corresponding test that:
1. Builds a minimal circuit (just that component + signal sources)
2. Runs the simulation to quiescence
3. Checks behavior via trace queries (not by inspecting node internals)
4. Uses a contract to express correctness

No reaching into `node.drivers` in test assertions — use `state_at(trace, t)` instead.

```cpp
// example test shape
TEST(NandGate, BothHighOutputLow) {
    Circuit circuit;
    auto a = circuit.add_node();
    auto b = circuit.add_node();
    auto y = circuit.add_node();
    nand_gate(circuit, {{"A", a}, {"B", b}, {"Y", y}});

    circuit.add_source(ScheduledSource{a, {
        {0, DriveIntent{"a", Signal::HIGH, Strength::STRONG}},
    }});
    circuit.add_source(ScheduledSource{b, {
        {0, DriveIntent{"b", Signal::HIGH, Strength::STRONG}},
    }});

    auto result = Simulator::run(circuit, SimConfig{.time_limit = 20});
    auto y_trace = result.traces.trace(y);
    EXPECT_EQ(state_at(y_trace, 15), Signal::LOW);
}
```
